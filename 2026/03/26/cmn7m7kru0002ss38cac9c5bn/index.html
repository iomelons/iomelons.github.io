AI Search Hub：一次提问，全域搜索的开源 AI 技能中枢
在构建 AI Agent 和自动化工作流时，获取高质量、多源信息往往是最耗时的环节。传统方式需要开发者自行维护大量爬虫、处理反爬机制、登录验证和结果解析，效率低下且易于失效。AI Search Hub（GitHub 项目：https://github.com/minsight-ai-info/AI-Search-Hub）正是为解决这一痛点而生的开源 Skill。它以 “One Query. All Search Skill.”（一次提问，全域搜索）为核心理念，将 Gemini、Grok、豆包、元宝等多家大厂 AI 平台的原生搜索和网页抽取能力聚合起来，形成一个统一、可复用的搜索中枢，直接服务于 Agent、OpenClaw 或各类自动化流程。0
项目核心价值：借力大厂，免除爬虫烦恼
AI Search Hub 的聪明之处在于“不重复造轮子”。它不自己去爬取数据，而是让各大 AI 平台利用其背后成熟的数据生态和优化后的搜索能力来完成任务。用户只需提供一次自然语言提问或指定链接，系统就会智能分发任务，各平台负责搜索、抽取、清洗和结构化，最终返回统一的结果。
这极大降低了维护成本：无需担心浏览器自动化、验证码、风控限流，也无需为每个平台单独编写解析规则。项目特别适合获取微信公众号、抖音、微博、B站、X（Twitter）等相对难爬的内容，以及科技趋势、行业舆情、旅行规划等日常场景。1
支持平台与智能路由
项目目前接入多家主流 AI 平台，每个平台凭借其母公司生态各有所长：
• Gemini（Google）：擅长全球网页发现和知识内容检索。
• Grok（xAI）：实时社交搜索，尤其精通 X/Twitter 动态和热点话题。
• 豆包（字节跳动）：中文热点归纳，覆盖抖音等内容。
• 元宝（腾讯）：微信公众号检索和中文信源补充。
• LongCat（美团）：中文知识与本地生活信息。
• 通义千问（阿里巴巴）：中文网页搜索。
• MiniMax：通用中文问答与生活类查询（近期新增支持）。
• 此外还包括 Kimi（长上下文处理）、Perplexity（网页摘要）、Claude（复杂推理总结）、文心一言（百度生态）等，并持续扩展。
系统内置智能路由逻辑（详见仓库 ROUTING.md），根据问题类型、语言和数据归属自动选择最优平台。例如，Twitter 相关用 Grok，中文热点用豆包，微信内容用元宝。这种设计确保覆盖面广且结果质量高。
工作流程简洁高效
整个过程形成一个闭环：
1 用户/Agent 输入一次提问。
2 系统根据路由规则分发到合适平台。
3 各平台利用原生能力完成搜索与抽取。
4 收集多平台结果，进行清洗和标准化融合。
5 输出结构化内容，直接供下游 Agent 或工作流使用。
这种“一次输入、多源输出”的模式，让信息获取变得像调用一个简单 API 一样便捷。
技术实现与快速上手
项目完全使用 Python 开发，代码简洁轻量。核心执行入口是 scripts/run_web_chat.py，支持命令行调用或集成到 Agent 配置中（例如通过 agents/openai.yaml）。
快速上手示例：

使用豆包规划新疆旅游路线

python3 scripts/run_web_chat.py
–site doubao
–prompt “帮我规划一下新疆旅游路线”
–output out/doubao_xinjiang_route.txt

使用 Grok 总结 Elon Musk 近期动态

python3 scripts/run_web_chat.py
–site grok
–prompt “请帮我总结 Elon Musk 在 X (Twitter) 上最近14天的一些动态，按日期倒序列出并附上链接”
项目还提供浏览器自动化支持（Chrome debug 模式），并附带详细的返回结果示例，如结构化的旅游行程或社交媒体动态总结。

适用场景与总结评价
AI Search Hub 特别适合以下人群：
• AI Agent 和 Multi-Agent 系统开发者，希望快速为工作流注入强大搜索能力。
• 研究、舆情监测和竞品分析人员，需要高效获取社交平台或公众号内容。
• 自动化工具爱好者，想减少爬虫维护负担，实现“指定链接免费抽取”。
总体而言，AI Search Hub 是一个思路清晰、定位精准的开源项目。它巧妙地利用大厂已打磨成熟的能力，显著降低了多源信息获取的门槛。目前社区反馈积极，扩展性强，是构建智能信息系统的实用工具。
